Intro
One of the most common data sources in
lakehouses is actually a file sitting in
an object store. Someone pushes their
CSV files or JSON files or just images
into your S3 bucket or Azure data lake
and now you have to figure out how do I
ingest this data incrementally into my
data platform such as datab bricks and
transform it into a proper lakehouse
format such as delta or iceberg. If you
implement this, you probably have the
following questions. How do I figure out
which files have I already processed? Do
I need to maintain a separate metadata
database only for that purpose? Also,
how do I make really sure I read the
files only once? And what do I do with
schema changes? And also, last but not
least, how do I archive or delete the
files that I have already processed so
that I don't have to store the files
twice? The answer for that in databris
is autoloader. This video will show you
hands-on how you can set up autoloader
within datab bricks together with
lakeflow declarative pipelines to build
this incremental file ingestion pipeline
and then also afterwards archive the
already processed data using the new
autoloader functionality called clean
source. This video is the third part of
an end toend databicks project. If you
want to know all the context about this
use case and the project we're working
on, I would recommend you to watch the
first and the second video. I will put
the links into the video description.
